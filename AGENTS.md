# AGENTS.md

- CPython tests need the native extension built (`python -m build`, then install the wheel, or an editable install). Run the module you changed: `python -m unittest tests/test_cpython_<module>.py`. Don't run the whole suite for a small change; it is long.
- The five gates CI runs: `python tests/parity/verify_acceptance.py`, `verify_effects.py`, `verify_streaming.py`, `verify_biquad.py` and `verify_mixdown_knee.py`. Lint is `python -m flake8` (defect checks only).
- The deeper parity gates need built interpreters and the pinned CircuitPython oracle. Pass `--micropython` and `--circuitpython` explicitly; `verify_dsp.py` refuses a run with fewer than two interpreters. A stock `circuitpython` build is not the oracle (it has 14 voices; the oracle has 64). See [Running the parity gates](docs/how-it-works/parity-gates.md).
- Never edit CircuitPython's own sources for the oracle, and never let a new module shadow one of CircuitPython's. Fixes for bugs that also exist upstream go in this repo's targets only, recorded in [upstream-diff](docs/how-it-works/upstream-diff.md); ask before adding a deviation.
- Don't re-capture a golden, or move `CIRCUITPYTHON_ORACLE` or `DEPENDENCIES.lock`, without independent evidence and the reason written down ([CONTRIBUTING.md](CONTRIBUTING.md#rules-that-keep-the-port-honest)).
- The `audiomp3` decoder is fetched, not vendored: `scripts/fetch_deps.sh` puts it under `.deps/`. Tremor (`audiovorbis`) is vendored in `third_party/tremor`.
- Import names match CircuitPython (`import audiocore`, `import synthio`), whichever runtime is underneath. The instrument and effect libraries live in [audiocomponents](https://github.com/PyDevices/audiocomponents), not here.
- A frozen module wins over `/lib` on MicroPython and CircuitPython, so a copied or mip-installed `audiodsp` never runs until you rebuild or put `/lib` first. On a source checkout set `PYTHONPATH` (CPython) or `MICROPYPATH` (MicroPython).
- What each module is held to: [the correctness standard](docs/how-it-works/correctness-standard.md). Where everything is: [How audiodsp works](docs/how-it-works/index.md).
- Examples follow one style. Start a file under `examples/` with the three REUSE licence lines the repo's other files use, then a docstring: a one-line imperative summary under 72 characters, a short paragraph on what it shows, then `Needs:`, `Run it:` and `Tested on:` in that order. `Tested on:` names only where the file ran, so run it before you write the line. Put the settings a reader may change in UPPER_CASE constants under a `# Change these to match your setup.` comment, and put a full-sentence comment above each step. Leave out issue numbers, bench port names and session history. If an example draws, use pygraphics, never `framebuf`. A style-only rewrite changes comments, docstrings and layout, never behaviour: compare the code with docstrings and comments stripped, before and after.
