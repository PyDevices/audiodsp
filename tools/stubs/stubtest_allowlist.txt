# What stubtest finds that the stubs do not change.
#
# The stubs describe the module built into MicroPython and CircuitPython. Each
# module also has a CPython twin in the wheel, and stubtest compares the stub
# with that twin. An entry here is either a point where CPython is built
# differently in a way no caller sees (the first block), or a difference
# between the two interpreters that audiodsp#426 lists (the second). Remove an
# entry when the difference is fixed: stubtest fails on an entry that matches
# nothing.
#
# Each line is a regular expression matched against the whole name.

# --- Differences in how CPython is built; no call written against the stub fails ---

# The CPython wrappers define __all__. The MicroPython modules have no __all__,
# so every public name is exported there.
[a-z0-9]+\.__all__

# Each CPython module re-exports a private helper base class, _AudioSample, and
# the stubs name that type another way. Nothing imports it.
[a-z0-9]+\._AudioSample(\..*)?

# The CPython wrappers set bits_per_sample and channel_count on the instance in
# __init__, so stubtest does not find them on the class. Every instance has them.
[a-z0-9]+\.[A-Za-z0-9]+\.(bits_per_sample|channel_count)

# The same, for the other attributes the CPython wrappers set on the instance.
audiosampler\.Sampler\.voice|audiomixer\.Mixer\.voice|synthio\.Biquad\.mode|synthio\.LFO\.waveform|synthio\.Synthesizer\.(blocks|refused)

# CPython builds these four enumerations on enum.Enum and MicroPython builds
# them as plain classes with the same members. The members and their names match.
synthio\.(FilterMode|EnvelopeState|MathOperation)(\.__new__)?
audiofilters\.DistortionMode(\.__new__)?

# RawSample and Graph are C extension types on CPython, which stubtest sees as
# final and with no readable signature. Graph's calls are checked by hand and
# match on both interpreters.
audiocore\.RawSample
audiograph\.Graph(\.__init__)?
